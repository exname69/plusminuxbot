# plusminuxbot — Telegram-бот для рабочих приходов и расходов

Пишешь `+100` (приход) или `-50 аренда` (расход). Комментарий необязателен. Данные хранятся в SQLite и **по желанию автоматически копируются в Google Sheets каждый день в 03:00**.

## 1. Запуск Docker

1. Создай бота у [@BotFather](https://t.me/BotFather) командой `/newbot` (или используй уже созданного), получи токен. В Telegram можно задать отображаемое имя `plusminuxbot` через `/setname` и username `plusminuxbot` через `/setusername`, если он свободен. Изменение кода **не меняет** имя в Telegram автоматически.
2. Перейди в папку `plusminuxbot`, создай `.env` из шаблона: `cp .env.example .env`.
3. Заполни `BOT_TOKEN` и при необходимости `BOT_TIMEZONE`, `CURRENCY`.
4. Запусти:

   ```bash
   docker compose up -d --build
   docker compose logs -f bot
   ```

5. Открой своего бота в Telegram, отправь `/start`, затем `+100` или `-50 аренда`.

Без настроек Google бот работает полностью автономно на SQLite.

> Если у тебя уже есть другой Docker Compose на этом VPS — это не проблема: используй отдельную папку проекта. Этот бот работает через Telegram long polling, не публикует порты.

## 2. Настройка автоматической выгрузки в Google Sheets

Один раз нужно настроить **Google Service Account**. Токен Telegram и ключ Google — разные вещи.

1. Создай **пустую Google Таблицу** в своём аккаунте: https://sheets.google.com/ . Назови, например, `plusminuxbot — резервные копии`. Не делай таблицу публичной.
2. Скопируй ID таблицы из адреса:

   ```text
   https://docs.google.com/spreadsheets/d/ВАШ_ID_ТАБЛИЦЫ/edit
   ```

3. Открой https://console.cloud.google.com/ , создай проект (или выбери существующий), включи **Google Sheets API** в разделе *APIs & Services → Library*.
4. В *IAM & Admin → Service Accounts* создай сервисный аккаунт. Для него в разделе **Keys** создай **JSON-ключ** и скачай его. Никакой OAuth-токен пользователя не требуется. Храни ключ только у себя.
5. В JSON-файле найди `client_email` сервисного аккаунта. Открой свою Google Таблицу, нажми **Настроить доступ / Share** и добавь этот `client_email` с правами **Редактор / Editor**. Не нужно давать сервисному аккаунту общие права на Google Drive.
6. Положи скачанный JSON в папку проекта под названием `secrets/service-account.json`.
7. Настрой права на ключ. Контейнер запускается под UID/GID **10001**:

   ```bash
   sudo chgrp 10001 secrets secrets/service-account.json
   chmod 750 secrets
   chmod 640 secrets/service-account.json
   ```

   При нестандартных UID/GID Docker на хосте проверь, что пользователь контейнера имеет право читать файл. **Не добавляй JSON-ключ в Git и не присылай его в чат.**

8. В `.env` допиши настройки:

   ```dotenv
   GOOGLE_SHEET_ID=ВАШ_ID_ТАБЛИЦЫ
   ADMIN_TELEGRAM_ID=ВАШ_TELEGRAM_ID
   BACKUP_HOUR=3
   BACKUP_RETENTION_DAYS=30
   ```

   Чтобы узнать свой Telegram ID, отправь боту `/id`. Переменную `GOOGLE_CREDENTIALS_FILE` из `.env.example` менять не нужно: Docker Compose сам задаёт путь `/secrets/service-account.json` внутри контейнера.

9. Перезапусти контейнер:

   ```bash
   docker compose up -d --build
   ```

10. Проверь настройку: в Telegram нажми **📤 Выгрузить** (доступно владельцу) или отправь `/backup`. Бот сообщит название снимка и ссылку на таблицу. В таблице появятся листы **Операции** и **backup_YYYYMMDD_HHMMSS_xxxxxx**.

**Если Google временно недоступен**, бот продолжит сохранять операции в SQLite. Автоматическая выгрузка повторится через 15 минут. При ошибке бот один раз за сутки отправит владельцу предупреждение (если настроен `ADMIN_TELEGRAM_ID`).

## 3. Как ведётся резервное копирование

- Каждый день в `BACKUP_HOUR:00` в часовом поясе `BOT_TIMEZONE` — по умолчанию **03:00**.
- Если сервер был выключен в 03:00, бот сделает пропущенную дневную копию **после следующего запуска**, если текущее местное время уже позже времени копирования.
- Копируется **вся история**, а не только операции за день: включая исправленные операции, отметки об удалениях, исходные ID и даты. Это необходимо для восстановления без дублей.
- Лист **Операции** содержит последнюю успешно выгруженную копию в читаемом виде. Он не синхронизируется в реальном времени.
- Каждый запуск выгрузки создаёт **отдельный датированный лист** `backup_...`; снимки за последние **30 дней** сохраняются. Этот срок можно изменить через `BACKUP_RETENTION_DAYS`.
- Снимок считается успешным только после завершения загрузки и проверки контрольной суммы SHA-256. Ручное изменение данных резервного листа приведёт к ошибке проверки при восстановлении.
- Даты и суммы на листе представлены в удобном виде, служебные столбцы позволяют восстановить полную SQLite-историю.
- Google Sheets — **резервная копия**, а не основная база данных. Изменения, внесённые вручную в Google Таблицу, **не отправляются** обратно в бота.
- При аварии VPS можно потерять операции, записанные после последней успешной выгрузки. Для более частого резервирования вручную используй `/backup`.

> **Приватность:** в таблицу попадут операции **всех пользователей этого бота**, включая Telegram ID. Не предоставляй доступ к таблице посторонним. Если бот используется только тобой, не распространяй ссылку на него.

## 4. Как восстановить SQLite после сбоя

Для этого есть **команды администратора на сервере** — случайно восстановить чужую или старую базу кнопкой в Telegram нельзя.

1. Важно: в той же папке проекта должны быть корректные `.env`, `secrets/service-account.json`. Если база была создана старым Compose-проектом, используй старое имя через `docker compose -p СТАРОЕ_ИМЯ ...` во **всех** командах ниже — иначе будет создан новый пустой volume.
2. **Останови основного бота**, чтобы во время восстановления не шли новые операции:

   ```bash
   docker compose stop bot
   ```

3. Посмотри список доступных копий (свежие сверху):

   ```bash
   docker compose run --rm --no-deps bot python -m app.backup_cli list
   ```

4. Восстанови **самую свежую проверенную копию**:

   ```bash
   docker compose run --rm --no-deps bot python -m app.backup_cli restore --confirm
   ```

   Или выбери конкретный снимок:

   ```bash
   docker compose run --rm --no-deps bot python -m app.backup_cli restore --sheet backup_20261109_030000_a1b2c3 --confirm
   ```

   Название после `--sheet` бери **из реального списка**, не используй пример буквально.

5. Команда **перед заменой** сохраняет локальную предыдущую базу файлом `/data/pre_restore_*.sqlite3`. Записи восстанавливаются атомарно (сохранение либо целиком, либо никак). Затем запусти:

   ```bash
   docker compose up -d bot
   docker compose logs -f bot
   ```

После восстановления новые операции будут получать новые ID, без конфликтов с историей. Проверка контрольной суммы защищает от случайно повреждённых резервных листов.

**Если отказал весь сервер**, перед восстановлением создай новый Docker volume (обычно он создаётся автоматически при `docker compose run`) и используй те же `.env` и JSON-ключ Google.

Также можно вручную создать резервный снимок через CLI, не отправляя команду в Telegram:

```bash
docker compose run --rm --no-deps bot python -m app.backup_cli backup
```

## 5. Команды Telegram

| Что написать | Результат |
|---|---|
| `+100` | Приход 100 |
| `-50` | Расход 50 |
| `+240 ногти` | Приход 240 с комментарием |
| `-300 материалы` | Расход 300 с комментарием |
| `вчера -800 аренда` | Внести расход за вчера |
| `сегодня` / `/today` | Отчёт за день |
| `неделя` / `/week` | Отчёт за неделю |
| `месяц` / `/month` | Отчёт за месяц |
| `история` / `/history` | Последние 10 операций |
| `отмена` / `/undo` | Удалить последнюю операцию |
| `остаток` / `/balance` | Итог всех приходов минус расходов |
| `/id` | Узнать Telegram ID |
| `/backup` | Немедленная выгрузка в Google Sheets (владелец) |

Можно отправить несколько строк за раз:

```text
+240 ногти
+180
-300 материалы
```

Под подтверждением одиночной операции есть кнопки **Изменить** и **Отменить**. Изменение: нажми кнопку, пришли новую строку, например `-350 материалы`. `/cancel` отменяет изменение.

### Почему «остаток» не всегда равен деньгам на руках

`остаток` здесь — сумма записанных приходов минус записанные расходы; если не внесён начальный баланс и все движения денег, это не фактический остаток кошелька.

## 6. Обновление старой версии бота

**Важно при переименовании:** в этом архиве имя Docker Compose-проекта — `plusminuxbot`. Если ты уже запускал старую версию как `plusminus_bot`, Docker Compose по умолчанию подключит **новый пустой** volume `plusminuxbot_bot_data`, а старая база останется в `plusminus_bot_bot_data`. Чтобы сохранить прежнюю базу и не переносить данные вручную, при обновлении укажи прежнее имя проекта:

```bash
docker compose ls                      # узнай имя старого проекта
docker compose -p plusminus_bot up -d --build
docker compose -p plusminus_bot logs -f bot
```

`plusminus_bot` — **только пример** старого имени. Используй фактическое имя из `docker compose ls` (особенно если ранее задавал `-p`). Это имя нужно сохранять и при следующих запусках/восстановлениях. При новой установке запускай без `-p`, будет использоваться `plusminuxbot`.

- Сохрани существующий `.env` и **не удаляй Compose volume**. Не выполняй `docker compose down -v`.
- Распакуй новые файлы в папку проекта (или поверх старых файлов), сохрани `.env`, JSON-ключ и **старый Docker volume**.
- Добавь в `.env` значения `GOOGLE_SHEET_ID`, `ADMIN_TELEGRAM_ID`, `BACKUP_HOUR`, `BACKUP_RETENTION_DAYS`.
- Положи JSON-ключ в `secrets/`, настрой права, затем запусти `docker compose up -d --build`.
- Изменений существующей таблицы `transactions` нет; добавляется только служебная таблица `backup_state`. Старые записи сохраняются.
- Не меняй фактическое имя Compose-проекта при обновлении: используй `-p СТАРОЕ_ИМЯ`, если до переименования проект назывался иначе.

## 7. Технологии и локальный запуск

- Python 3.12, aiogram 3, SQLite, Google Sheets API v4, Google Service Account.
- Docker Compose и постоянный volume `/data`.
- SQLite хранит суммы **целыми сотыми**, `float` для денег не используется.
- Восстановление проверяет целостность снимка; изменения SQLite выполняются транзакционно.
- Для одного токена Telegram запускай **один polling-процесс** (не два экземпляра бота с тем же токеном).

Без Docker:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# заполни токен и, если нужно, Google-параметры
python -m app.bot
```

Тесты (офлайн, без реального Google API):

```bash
python -m unittest discover -s tests -v
```

Если сервисный аккаунт или ID таблицы неверны, увидишь ошибку в логах:

```bash
docker compose logs --tail=100 bot
```
